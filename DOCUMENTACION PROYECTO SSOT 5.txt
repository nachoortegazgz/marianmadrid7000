## 🟠 PRIORIDAD 6 — MOTOR DE RESERVAS (FLUJO CRÍTICO)

### Arquitectura de 3 capas

```
reservas.web.js (Disponibilidad)
       ↓
bookingSaga.js (Orquestación Saga)
       ↓
bookingCore.js (Primitivas atómicas)
```

### Modelo de servicio dual con gap

```
F1 (Aplicación) → Gap/Exposición → F2 (Aclarado)
phase1Duration      exposureDuration    phase2Duration
██████████░░░░░░░░░░░░░░░░░░░░░░░████████████
│← Ocupada →│← Libre →│← Ocup. →│
```

### Idempotencia (3 capas)

1. `pairToken` determinista: `SHA256(serviceId + resourceId + f1Start + f2Start) + emailHash`
2. `BookingTransactions`: `transactionId = SHA256(pairToken + payloadHash)[:16]`
3. Query por `pairToken` en `CitasF2` antes de ejecutar Saga

### Limitaciones pendientes (bloqueantes)

| Limitación | Impacto |
|---|---|
| `_persistBooking` no escribe campos canónicos en CitasF2 | Balanceo parcial para citas nuevas |
| `meta` serializado como `JSON.stringify` | Impide consultas por subcampos |
| Rate limiter sin persistencia de violaciones | Abuso sobrevive cold starts |
| Caché dual sin invalidación individual por pairToken | Pares expirados no se borran por evento |
| `_resolveStaffForSlotInternal` es stub | Revalidación real no funciona |

## 🟠 PRIORIDAD 7 — CAJA, CONTABILIDAD Y CUMPLIMIENTO

### Ruta canónica de toda operación económica

```
Evento Wix o acción autorizada
    ↓
Validación permisos + idempotencia
    ↓
Recálculo servidor (importes, impuestos, stock)
    ↓
Registro ledger fiscal (MovimientosCaja)
    ↓
Registro contable (AsientosContables + LineasAsientoContable)
    ↓
Registro auditoría (MmAuditLog + EventosSistemaFacturacion)
    ↓
Exportación documental al contable
```

### Cadena de integridad fiscal

```
canonicalPayload = JSON normalizado campos fiscales
currentRecordHash = SHA256(canonicalPayload + previousRecordHash)
digitalSignature = HMAC_SHA256(currentRecordHash, FISCAL_KEY)
```
